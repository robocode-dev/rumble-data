# VIS-001 — Your product or system

<!-- clue:vision:bootstrap -->

Replace this bootstrap with your own direction before running `clue validate`. If this repository is deliberately not stating one, delete this file — an absent vision is valid, and only an unreplaced bootstrap fails.

Keep it to roughly one screen. It is read while orienting, so length is a cost paid on every read. Answer, in whatever prose suits you:

- What is this product or system?
- Whom does it serve?
- What problem, need, or opportunity does it address, and what value does it intend to create?
- What is inside its scope, and what is deliberately outside it?
- What principles or differentiators constrain its direction?
- How would stakeholders recognize that it is succeeding?
- Which important assumptions are still uncertain?

This is not a roadmap, a backlog, an architecture document, a set of requirements, or a marketing statement. It does not need a business case, and it works the same for a commercial product, an internal system, a library, a platform, or an open-source project. Goals link here (`links: [VIS-001]`); this file does not list them, and a change edits it only when the direction itself changes.

If an agent drafted this from repository evidence rather than from your answers, it stays `status: draft` with `provenance: inferred` and `reversal-cost: low|high` until you confirm it. Remove `reversal-cost` when you promote it: the field classifies deferred inference, not verified meaning. That is the corpus's ordinary way of saying no human has agreed to this yet.
